Box 4 is the only one on the internet

Boxes 1–3 all live on your own machine — you can do everything so far on a plane with the wifi off. Only git push crosses into box 4, and only git fetch and git pull come back the other way.

Press Someone edits on GitHub above to see what happens when box 4 gains a commit you don't have — it's the exact situation you'll create on purpose in Step 07, and the reason git push sometimes refuses.

The thing that confuses everybody

Run git add, then git diff — nothing appears, and you assume it broke. It didn't. Plain git diff compares box 1 against box 2, and after staging they're identical. The question you meant to ask is git diff --staged, which compares box 2 against box 3. Try both above.

03

Merge vs Rebase

Two ways to bring a branch back together with main. Press the buttons and watch what happens to the commits — especially to their names.

Starting point
Your branch split off, and main moved on
git mergegit rebase
Does whatTies both lines together with one new merge commitCopies your commits on top of the newest main
Your commit IDsUnchangedAll new. Same changes, different commits
History showsWhat actually happenedA tidier story that isn't literally true
Then push isNormalRejected — needs --force-with-lease
Safe on a shared branch?YesNo
Working solo? Here's the honest answer

While you're the only person on the repo, this choice barely matters — you can't disrupt anyone. Use merge; it's the safe default and it's what the buttons on GitHub do. Learn rebase now so the word isn't scary later, but don't agonise over it. The one rule that will matter the day you work with someone: never rebase a branch other people have already pulled.

04

Reading a Conflict

A conflict is not an error and you have not broken anything. It's Git saying: the same line changed in two places and I won't guess which one wins. It's the one moment Git refuses to be clever.

Click any line to identify it
What the markers mean

      


      

        The trap
        
In a merge, HEAD is your side. In a
        rebase, HEAD is the other side and your work
        is on the bottom. They're swapped.

        
How to tell which you're in: look at the bottom
        marker. A branch name means merge. A commit ID and message means rebase.
        Or just run git status — it says so on the first line.

      The fear, and the cure
      
Beginners are scared of Git because they think they can permanently destroy their work.
      Once a change is committed, it is very hard to lose — git reflog
      remembers roughly 90 days of everything you did, even things you "deleted".

      
One real exception: git reset --hard destroys changes
      you hadn't committed, and nothing brings those back. Which is the whole argument for
      committing early and often. A commit is a save point.

09
Adding Player 2

    
Everything above works alone. The moment a second person joins, four new ideas
    show up. This is a map, not a lesson — come back when you actually have someone to work with.


    

      
IdeaWhat changes

      
        
CollaboratorsSettings → Collaborators → Add people. They must accept the invite before they can push — this is the single most common ten-minute stall

        
ForksFor people you don't want pushing to your repo. They copy it, work there, and send a pull request back. This is how you contribute to strangers' open-source projects

        
ReviewNow your pull request has an audience. Someone clicks a line and comments. You cannot approve your own PR — that's the point of it

        
Real conflictsNow they happen by accident instead of on purpose. Nothing new to learn — you already did this in Step 07 — but git pull before you start work becomes a habit rather than a nicety

      
    


    

      One habit to start now, while alone
      
Write commit messages as if a stranger will read them, because in six months
      you are that stranger. "Fix bug" tells you nothing. "Fix crash when the
      search box is empty" tells you everything. This is the single habit that separates people who
      are comfortable in a codebase from people who aren't — and you can practise it entirely alone.
